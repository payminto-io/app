## Rulings

- **C1** (`71ad581`). `processSignature` fetches from up to two pool picks (`Client.GetTransactionFromNodes`); a signature no node returns is `errTransientFetch`, the cursor stays below it and the account records `held_signature` / `held_attempts`. After `MaxHeldAttempts` (12 ticks) a `solana_unresolved_signature` anomaly is written, the signature moves to `unresolved_signatures` (JSON array on the account) where it is retried on its own each tick, and later signatures proceed with the cursor. Already-recorded signatures are not re-fetched. Tests: `TestSolanaDeposit_C1_NullTransactionHoldsTheCursorAndCreditsLater` (reviewer's probe: null once, then the fixture; the deposit is credited on the next tick, no `DEPOSIT LOST`), `TestSolanaDeposit_C1_UnresolvedSignatureIsAnomalyThenCredited`, `TestClient_GetTransactionFromNodesTriesOtherNodes` (two httptest nodes, one lagging).
- **I1** (`71ad581`). `evidencedDrop`: past the grace, the finalized slot (`getSlot` finalized) must exceed the deposit's slot and `getTransaction` at finalized must be nil on at least two pool picks; a single node's unknown only touches `updated_at`. `ConfirmOnce` also lists `failed` deposits younger than `ReviveWindow` (7 days); a non-null status revives them (`confirming`, or straight to `confirmed` when finalized) and `finalize` accepts `failed` rows, so the journal (keyed by deposit id) posts once. Test: `TestSolanaDeposit_I1_DropNeedsFinalizedEvidenceAndRevives` (reviewer's scenario end to end, journal counted once).
- **I2** (`dfdddc3`). `solana_sweep_attempts` records every broadcast (signature, blockhash, `lastValidBlockHeight`, status sent/landed/expired/failed); `solana_sweep_deposits` records the deposits a sweep claimed. `TrackConfirmations` fetches statuses for all attempts, books the first finalized one (`book`), marks the others expired or failed, and is idempotent through the sweep's completion. A rebuild happens only when every attempt is unknown, the finalized block height is past the latest attempt's validity, the signature is absent at finalized on more than one node, and every account still holds its balance (an empty account while no attempt is finalized means "wait"). "Holds nothing" never marks swept: `explainDrain` looks for one of our attempt signatures in the account's history; otherwise `solana_unexplained_drain` is recorded and the account is set aside (`drained`), its deposits stay `confirmed`. `reconcile` compares the hot ATA's balance delta in the landed transaction with the booked total and raises `solana_sweep_mismatch`. Tests: `TestSolanaSweep_I2_LandedRebuildIsBookedOnce` (reviewer's scenario A: attempt 1 lands late, attempt 2 fails; booked once, no anomaly), `TestSolanaSweep_I2_HoldsNothingIsAnomalyNotSwept`, `TestSolanaSweep_I2_ReconcileMismatchRaisesAnomaly`, `TestSolanaSweep_ExpiredWithoutLandingReleasesDeposits`.
- **I3** (`29f2ea0`, `0990369`). `ParseKeypair` accepts a 64- or 32-byte base58 secret, a JSON byte array, or `file:<path>`; a bare value is never read as a path and every failure is the fixed `ErrKeypairFormat` (or "keypair file could not be read"), no input in any error. `WireSolana` wraps it without adding the value. Tests: `TestParseKeypair_NeverEchoesTheInput` (reviewer's probe), `TestWireSolana_MistypedFeePayerKeyNeverReachesLogs` (captures `log` output and the error and asserts the typo'd and the real key never appear).
- **I4** (`29f2ea0`). `ExtractDeposits` credits the ATA's balance delta for the transaction; `delta < parsed` is a `withheld_amount` anomaly, `delta > parsed` stays `unparsed_credit`. Token-2022 remains rejected unless the row is `SPL-2022`. Test: `TestExtractDeposits_WithheldAmountCreditsDeltaAndFlags` (reviewer's probe: instruction 25, account rises 24; credit 24, anomaly 1).
- **I5** (`71ad581`, `29f2ea0`, `0990369`). ## Double booking with the switch

`SolanaDepositService` posts the deposit's payment journal at finalization only when its `ledger` is non-nil. The flag is `SOLANA_POST_DEPOSIT_JOURNALS` (`config.SolanaConfig.PostDepositJournals`, default true). The switch merge should set it false in the deployment configuration or default it to false in `config.go`; the call it disables is `LedgerService.RecordDepositIn` inside `SolanaDepositService.finalize` (`backend/internal/service/solana_deposit_service.go`), wired in `ServiceRegistry.wireSolana` (`solana_wiring.go`, `depositLedger` nil when the flag is off). Test: `TestSolanaDeposit_JournalPostingIsOptional`. Per the switch review, `LedgerService.RecordPaymentDeposit` has no production caller, so this is the only overlap.
