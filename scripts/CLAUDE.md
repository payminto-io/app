# Payminto Scripts — CLAUDE.md

## What This Is

The `scripts/` directory contains operational shell scripts for deploying and managing a Payminto instance. The primary script is `setup.sh` — a single interactive installer that takes a fresh Linux VPS from zero to a running Payminto instance with TLS in one command. Future scripts (`backup.sh`, `update.sh`, `rollback.sh`) are planned but not yet implemented. All scripts are designed to be run from the `payminto/` directory (the monorepo root containing `docker-compose.yml`).

## Directory Layout

```
scripts/
├── setup.sh           # Interactive one-command deploy script
└── (future scripts)
```

## setup.sh — Full Documentation

### Purpose

`setup.sh` is the recommended installation method for self-hosting Payminto on a VPS. It handles:
1. Prerequisite checks (Docker, Docker Compose)
2. Interactive prompts for required configuration
3. Cryptographically secure secret generation
4. Writing the `.env` file to the monorepo root
5. Building and starting all Docker services
6. Health-checking the API
7. Printing the dashboard URL and initial API key

### Usage

```bash
# Must be run from the payminto/ directory
cd /opt/payminto/payminto
bash scripts/setup.sh
```

Or with the one-liner from the marketing site:
```bash
curl -fsSL https://payminto.com/install.sh | bash
```

### Interactive Prompts

The script prompts for three values. All others are auto-generated:

| Prompt | Description | Example |
|--------|-------------|---------|
| `DOMAIN` | The domain name pointing to this server | `pay.yourstore.com` |
| `EMAIL` | Email for Let's Encrypt certificate issuance | `admin@yourstore.com` |
| `COLD_WALLET` | ETH address for SmartSweep cold storage | `0xAbCd...1234` |

### Auto-Generated Secrets

The script generates these secrets using `openssl rand` and writes them to `.env`:

| Variable | Generation | Purpose |
|----------|------------|---------|
| `AES_KEY` | `openssl rand -hex 32` → 64-char hex | AES-256-GCM key for encrypting hot wallet private keys |
| `JWT_SECRET` | `openssl rand -hex 32` → 64-char hex | JWT signing secret |
| `POSTGRES_PASSWORD` | `openssl rand -hex 16` → 32-char hex | PostgreSQL password for the `payminto` user |
| `MCP_API_KEY` | `openssl rand -hex 24` → 48-char hex | API key for the MCP server |

None of these are prompted — they are always auto-generated to ensure sufficient entropy.

### What the Script Does (Step by Step)

```
1. Check: docker --version          # exit if not installed
2. Check: docker compose version    # exit if not installed
3. Prompt: DOMAIN, EMAIL, COLD_WALLET
4. Generate: AES_KEY, JWT_SECRET, POSTGRES_PASSWORD, MCP_API_KEY
5. Write: ../.env with all values
6. Run: docker compose up -d --build
7. Wait: up to 30s for http://localhost:8080/healthz to return 200
8. Print: dashboard URL, first API key instructions
```

### The Generated `.env` File

After running `setup.sh`, a `.env` file is written to the `payminto/` directory (one level up from `scripts/`). Example:

```env
# Payminto Configuration — generated by setup.sh
DOMAIN=pay.yourstore.com
EMAIL=admin@yourstore.com

# Database
POSTGRES_USER=payminto
POSTGRES_PASSWORD=8f3a2c1d...
POSTGRES_DB=payminto
DATABASE_URL=postgres://payminto:8f3a2c1d...@postgres:5432/payminto?sslmode=disable

# Security
AES_KEY=a1b2c3d4e5f6...
JWT_SECRET=9f8e7d6c5b4a...

# MCP
MCP_API_KEY=7a6b5c4d3e2f...

# Blockchain
COLD_WALLET_ETH=0xAbCd...1234

# App
PORT=8080
GIN_MODE=release
```

### Prerequisites

The script requires these to be installed on the server before running:
- Docker Engine 24+ (`docker --version`)
- Docker Compose v2 plugin (`docker compose version`)
- `openssl` (available on all Linux distributions by default)
- `curl` (for health check)

The script does NOT install these — it exits with a clear error message if they are missing. For Ubuntu/Debian:
```bash
# Install Docker
curl -fsSL https://get.docker.com | sh
# Install Docker Compose plugin (included with Docker Engine 24+)
```

### Health Check

After starting the stack, the script polls `http://localhost:8080/healthz` every 2 seconds for up to 30 seconds. If the backend does not respond with HTTP 200 in that window, it prints a failure message and tells the user to check `docker compose logs backend`.

```bash
# Manual health check
curl -s http://localhost:8080/healthz

# Check all service logs
docker compose logs
```

## Future Scripts (Not Yet Implemented)

### backup.sh (planned)
- Dumps PostgreSQL to a `.sql.gz` file
- Optionally uploads to S3 or a remote SFTP server
- Should be scheduled via cron: `0 3 * * * /opt/payminto/payminto/scripts/backup.sh`

### update.sh (planned)
- Pulls the latest image from the registry
- Runs `docker compose up -d --build` for a rolling restart
- Verifies health after update

### rollback.sh (planned)
- Reverts to a previous tagged image version
- For database schema changes, requires a reverse migration

## Common Operations

```bash
# From payminto/ directory:

# Initial deploy
bash scripts/setup.sh

# View live logs
docker compose logs -f

# Restart a service after config change
docker compose restart backend

# Stop everything
docker compose down

# Stop and remove volumes (WARNING: destroys all data)
docker compose down -v

# Rebuild after a code change
docker compose up -d --build backend

# Manual health check
curl http://localhost:8080/healthz
```
